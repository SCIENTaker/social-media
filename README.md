# つながりDB(仮)

配信者・VTuberの「誰と誰がどうつながっているか」を、**出典付きの関係図**で見られるサイトです。
個人の詳細情報は既存Wikiに任せ、関係性の可視化に特化しています。

> 現在のデータは **にじさんじ・ぶいすぽっ!の仮データ**(人物49人・イベント8件)です。
> 出典は公式発表を報じた報道記事(`kind: "news"`)を暫定で使っており、公式発表・配信アーカイブへの差し替えが必要です。
> 2026年10月時点の公開情報を検索して確認できた事実だけを入れていますが、網羅はしていません(にじさんじは一部のライバーのみ)。

## 主な画面

URL はハッシュ方式(例: `https://example.com/#/p/higuchi-kaede`)です。サーバー側の設定なしで、どの静的ホスティングでもページ遷移・再読み込み・共有URLが動きます。

| URL(`#` 以降) | 画面 |
| --- | --- |
| `/` | トップ(検索・最近のコラボ・事務所/イベントへの入口) |
| `/p/:id` | 人物ページ。本人中心の関係図、期間・関係種別の絞り込み(URLに保存されるので共有可)、共演回数順の一覧 |
| `/pair/:a/:b` | 2人の関係ビュー。関係の種類と根拠、共演配信一覧(年で絞り込み)、共通の共演者 |
| `/org/:id` | 組織ページ。期生ごとの所属者、組織内の共演マップ(表) |
| `/event/:id` | イベントページ。参加者・チーム分け・出典 |
| `/path?from=&to=` | 経路検索(2人をつなぐ最短の共演の連なり) |
| `/submit` | 情報提供フォーム(出典URL必須。GitHub Issue の下書きを開く) |
| `/policy`, `/changes` | 掲載基準・コンテンツポリシー、変更履歴 |

## 技術構成

- Vite + React + TypeScript(静的サイト。バックエンド不要)
- 関係図: Cytoscape.js
- データ: `src/data/*.json`(Git で管理し、PR で変更 → レビュー = 承認フロー)

仕様書の Next.js + PostgreSQL 案に対し、MVP は「JSON を Git 管理+静的配信」にしています。
編集者の承認を Pull Request のレビューで代替でき、変更履歴も Git に残るため、少人数運営で始めやすい構成です。
データが数千人規模になったら、同じ型定義(`src/lib/types.ts`)のまま DB へ移行できます。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm test           # 集計ロジックとデータ整合性のテスト
npm run validate   # データの検査(出典の有無・ID参照・禁止ドメインなど)
npm run build      # 検査 → 型チェック → dist/ に出力
```

`dist/` をそのまま置けば動きます(Vercel / Netlify / Cloudflare Pages / GitHub Pages、サブディレクトリでも可。リライト設定は不要)。

## データの追加方法

`src/data/` の JSON を編集します。

| ファイル | 内容 |
| --- | --- |
| `persons.json` | 人物(表示名・読み・別名/旧名・種別・活動状態・公式リンク・一言紹介) |
| `orgs.json` | 組織(事務所 / ユニット / チーム。`parent` で親組織) |
| `memberships.json` | 所属(期生・開始日・終了日。卒業は `end` で表す) |
| `events.json` | コラボ配信・歌/動画・企画・大会と参加者。**共演回数はここから自動集計** |
| `relations.json` | 制作(絵師・モデラー・楽曲提供)と、本人が公言した関係のみ |
| `sources.json` | 出典(配信アーカイブ / 公式発表 / 本人投稿 / 報道記事)。関係・イベント・所属はすべて出典必須 |
| `changes.json` | 公開する変更履歴 |

ルール:

- 「公式所属」は所属データから、「共演」「企画・大会」はイベントから算出するため、`relations.json` には書かない
- 「公式所属」の線を引くのは、同じユニット・グループ・チームと、事務所の同期(`role` が同じ)だけ。同じ事務所というだけの相手は図に出さない(大きな事務所で図が埋まるため)
- チーム分けのある大会は `teams` を書く。同じチームのメンバー同士だけが関係として数えられる
- 主催が未掲載の人物・団体なら `host` の代わりに `hostName` に名前を書く
- 引退後に関係情報の非公開を求めた人物は `"visibility": "basic-only"` にすると、関係図・イベント参加者から外れ、基本情報だけが残る
- 「前世」「中の人」、仲の良し悪し、まとめサイト・掲示板を出典とする情報は載せない(`/policy` 参照)

`npm run validate` は CI でも実行する想定です(出典のない関係や存在しない人物IDがあるとビルドが失敗します)。

## 仕様書から変えた点・未対応

- 自動収集(YouTube/Twitch API)と管理画面は未実装。当面は JSON への PR で運用
- 情報提供フォームは送信先サーバーを持たず、GitHub Issue の下書きを開く方式
- 組織内の共演マップは、読みやすさを優先して図ではなく表(ヒートマップ)にした
- 未決事項「共演とみなす条件」は、仮に「大会は同じチームのみ」とした(`src/lib/db.ts` の `coParticipants`)
- 人物の公式リンクは仮に事務所サイトとYouTube検索にしている。各人の公式チャンネルURLに差し替える
- 「制作」「公言された関係」(`relations.json`)は、一次出典を確認できたものがまだないため空
